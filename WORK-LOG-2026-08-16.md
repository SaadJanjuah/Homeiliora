## 🔬 On measuring rather than eyeballing

Contrast over the hero photographs was set by **sampling the rendered pixels** — the hero captured with its text hidden, at three points in the cross-fade, in both themes, scoring the *worst* pixel in each text box rather than the average. It caught four things that looked fine:

| | Measured | After |
|---|---|---|
| v1 pale scrim, eyebrow + dek | 2.52:1 | — (approach abandoned) |
| Text centred, not left (v2) | 1.17:1 | 5.06:1 |
| Eyebrow, two hundredths short | 4.48:1 | 9.41:1 |
| Lines centred inside the column (v3) | 2.04:1 | 8.31:1 |

**The sampler also had a blind spot worth recording.** It measures text against the *photograph*, but a button label sits on its own opaque fill — so it scored the CTAs 12–16:1 while the dark-mode label was actually **3.0:1**, white on lifted terracotta. Found by checking label-against-fill separately; dark mode now flips the label rather than the fill. A passing check is only as good as what it actually asserts.

## ⚠️ Traps hit more than once — worth knowing before the next change

1. **WordPress's constrained layout caps and centres every direct child**, at every nesting level, with `margin: auto !important`. It bit four times: the hero backdrop rendered as a 720px strip inside a full-width band; the header nav was stuck at 420px; the hero text block sat centred over the bright half of the photo; and the individual lines did the same one level deeper. Absolutely-positioned children are not exempt.
2. **New files in `patterns/` render as nothing** until WordPress's pattern-list cache expires — indistinguishable from broken markup. `WP_DEVELOPMENT_MODE = 'theme'` is now set in the local `wp-config.php`. **Do not set it in production.**
3. **Headless Chrome defaults to a dark colour scheme**, so a "light mode" test that does not emulate light explicitly silently measures dark. One run of the contrast sampler was invalid because of this.
4. **Screenshots can lie.** A dropdown appeared see-through in headless captures while the DOM, hit-testing and computed styles all said opaque — confirmed correct with a headful capture. Separately, a stale LiteSpeed render showed an old layout after the CSS had already changed. Measure the boxes, don't trust the picture.
