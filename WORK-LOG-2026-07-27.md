### 3. Dark mode — new feature
- [x] Light/dark theming with a toggle in the header beside the search icon
- [x] Defaults to the reader's OS setting; clicking stores an explicit choice in `localStorage`
      (`homeiliora_theme_v1`) that overrides the OS **in both directions** and syncs across tabs
- [x] **No flash of light on load** — an inline snippet in `wp_head` applies the stored choice before first paint
- [x] Built by re-pointing the `--wp--preset--color--*` variables in a new `assets/css/dark.css`, so
      `theme.json`, block markup and `main.css` all follow from one place and cannot drift apart.
      `dark.css` holds no layout or component rules — if it fails to load the site renders exactly as before.
- [x] Warm-charcoal palette, not neutral grey; terracotta and forest lifted (`#D9643A`→`#E4764C`,
      `#3F5D42`→`#86A98A`) because the originals were chosen against warm plaster. Every text pairing
      measured at **WCAG AA or better** — lowest is 5.3:1.
- [x] The footer stays a dark band in **both** themes (it is painted with the very presets dark mode
      flips, so its colours are pinned to their own tokens)

### 4. Ad rails — now actually visible at 100% zoom
- [x] **Was:** gated at `min-width: 1560px`, which no ordinary laptop reaches at 100% zoom —
      1920×1080 at Windows' default 125% scaling is a 1536px viewport. The rails only appeared when
      the page was zoomed out. At exactly 1560px the unit also overlapped the content column by 4px.
- [x] **Root cause:** not the breakpoint — a 1200px content column leaves no gutter at all on a normal
      laptop. The wide column now caps at `min(1200px, 100vw - 320px)`, one override of
      `--wp--style--global--wide-size` (the single property WordPress uses for every alignwide block),
      so no templates or per-block rules changed.
- [x] Costs nothing from 1520px up; below that the column gives back exactly what the rails need.
      **The 720px reading column is untouched at every width**, so body copy never narrows.
- [x] Rails are centred in the gutter instead of pinned to the viewport edge, and step between the two
      standard IAB sizes: 120×600 from 1200px, 160×600 from 1620px
- [x] Verified 1152→2560px on home and single: rails from 1200px, clearance never below 20px, no
      overlap, no horizontal scroll

### 5. Sticky header — fixed
- [x] **Was:** the nav bar scrolled away with the page despite `position: sticky` being set
- [x] **Root cause:** the sticky was on `.site-header`, but WordPress wraps every template part in its
      own element and that wrapper was **exactly as tall as the header** (120px both). A sticky element
      can only travel inside its parent's box, so it stuck for zero pixels. The CSS computed as sticky
      the whole time, which is why it looked correct.
- [x] Moved the stick to `header.wp-block-template-part`, whose parent is `.wp-site-blocks` — the full
      document. Added `scroll-padding-top` so in-page anchors clear the now-permanent header.
- [x] Verified on 5 templates × 5 widths (390–1920px): all pin at `top: 0`, nothing painting over them

### 6. Brand lockup — horizontal, and bigger
- [x] Mark now sits **beside** the wordmark rather than stacked above it. Wordmark **12px → 24px**
      *and* the header **120px → 70px** (15% → 8.8% of a laptop screen) — bigger logo *and* more room
      for content, which matters now the header is sticky.
- [x] **Found:** the old logo was an `<img>`-referenced SVG — an isolated document that cannot reach
      the page's `@font-face` rules. The wordmark had been silently rendering in **Arial, not Space
      Grotesk**. It is now real HTML text in the actual brand font: crisp at any size, selectable, translatable.
- [x] Mark is inlined SVG using `currentColor` + the colour presets, so it adapts to both themes with
      **no second asset** — which retired the dark logo variant built earlier in the session
      (`logo-stacked-dark.svg` deleted; `logo-stacked.svg` untouched as a brand asset)
- [x] One knob (`--md-mark-h`) scales the whole lockup; the wordmark's rule is positioned from it so
      both brand rules stay on a single line (they had been drifting ~2.4px apart)
- [x] Three size bands keep the header one row from 360px up. 600–700px is tightest: core swaps back
      to the full nav at exactly 600px but the nav needs ~640px. Scanned every 4px from 360→1000px.
